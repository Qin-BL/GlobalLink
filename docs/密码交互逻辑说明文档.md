# 密码交互逻辑说明文档

## 1. 概述

本文档详细说明GlobalLink系统中密码的交互流程、加密机制以及安全设计，旨在确保用户密码在传输和存储过程中的安全性。

## 2. 系统架构

GlobalLink系统采用前后端分离架构，密码交互主要涉及以下组件：

- **前端**：React应用，负责用户界面和密码加密
- **后端**：FastAPI应用，负责密码验证和用户认证
- **数据库**：存储用户信息和密码哈希值
- **传输层**：HTTPS协议确保传输安全

## 3. 密码加密机制

### 3.1 前端加密

系统前端使用Web Crypto API实现密码加密，主要通过以下步骤：

1. **加密函数**：`encryptPassword` 函数（位于passwordEncrypt.js）
2. **加密算法**：SHA-256哈希算法
3. **组合字符串**：密码 + 时间戳 + 随机盐值 + 域名
4. **加密数据格式**：JSON对象，包含哈希值、时间戳、盐值和域名信息

关键代码实现：

```javascript
// 前端密码加密示例
function encryptPassword(password) {
    timestamp = int(datetime.now().timestamp() * 1000);
    random_salt = generateSalt();
    domain = window.location.origin;
    
    // 组合字符串
    combined_string = `${password}:${timestamp}:${random_salt}:${domain}`;
    
    // 使用SHA-256哈希
    hash_result = hashlib.sha256(combined_string.encode()).hexdigest();
    
    // 返回加密数据
    return JSON.stringify({
        'hash': hash_result,
        'timestamp': timestamp,
        'salt': random_salt,
        'domain': domain
    });
}
```

## 4. 密码交互流程

### 4.1 管理员登录流程

1. **用户输入**：管理员在登录界面输入用户名和密码
2. **前端加密**：`AdminLogin.js` 调用 `encryptPassword` 函数加密密码
3. **请求发送**：通过fetch API发送POST请求到 `/api/v1/admin/login` 端点
4. **后端处理**：`admin.py` 接收请求，调用 `decrypt_user_password` 解密密码
5. **密码验证**：使用 `security.verify_password` 验证解密后的密码与数据库存储的哈希值
6. **令牌生成**：验证成功后，生成访问令牌和刷新令牌并返回

### 4.2 普通用户登录流程

普通用户登录流程与管理员登录流程类似，但通过不同的API端点和处理逻辑：

1. **用户输入**：用户在登录界面输入用户名和密码
2. **前端加密**：通过Redux的login action调用 `encryptPassword` 函数加密密码
3. **请求发送**：发送POST请求到 `/api/v1/auth/login/custom` 端点
4. **后端处理**：后端接收请求，解密并验证密码
5. **令牌生成**：验证成功后，生成访问令牌并返回

## 5. 密码存储安全

系统采用多层安全机制确保密码存储安全：

1. **哈希算法**：使用bcrypt算法对密码进行哈希处理
2. **盐值**：每个密码都使用唯一的盐值进行哈希
3. **工作因子**：配置适当的工作因子，增加破解难度
4. **不可逆存储**：数据库中只存储密码的哈希值，不存储明文密码

关键代码实现：

```python
# 密码哈希生成
def get_password_hash(password: str) -> str:
    return pwd_context.hash(password)

# 密码验证
def verify_password(plain_password: str, hashed_password: str) -> bool:
    return pwd_context.verify(plain_password, hashed_password)
```

## 6. 传输安全

系统采用HTTPS协议确保密码在传输过程中的安全：

1. **SSL/TLS加密**：配置TLS 1.2/1.3协议加密传输数据
2. **HTTP重定向**：自动将HTTP请求重定向到HTTPS
3. **安全头部**：配置适当的HTTP安全头部，如HSTS

Nginx配置示例：

```nginx
# HTTPS配置
server {
    listen 443 ssl;
    server_name globallink.com;
    
    ssl_certificate /etc/ssl/certs/globallink.crt;
    ssl_certificate_key /etc/ssl/private/globallink.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;
    
    # HTTP安全头部
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    # ...其他配置...
}

# HTTP重定向到HTTPS
server {
    listen 80;
    server_name globallink.com;
    return 301 https://$host$request_uri;
}
```

## 7. 安全优化建议

虽然当前系统已经实现了多层安全机制，但仍有以下优化建议：

1. **密钥管理**：加强加密密钥的管理，定期轮换密钥
2. **超时验证**：增加对加密时间戳的验证，防止重放攻击
3. **双因素认证**：为管理员账户和敏感操作添加双因素认证
4. **密码策略**：实施更严格的密码策略，包括长度、复杂度和定期更换要求
5. **审计日志**：记录所有密码验证尝试，便于安全审计和异常检测

## 8. 常见问题处理

### 8.1 解密失败

如果后端解密密码失败，系统会自动降级为使用明文密码进行验证。这确保了在加密机制出现问题时，系统仍然可以正常工作。

### 8.2 浏览器兼容性

系统会检查浏览器是否支持Web Crypto API，如果不支持，则直接使用明文密码传输（但仍通过HTTPS协议）。

### 8.3 性能考虑

密码加密和解密操作可能会对系统性能产生一定影响。系统采用异步处理和线程池执行密集型操作，以最小化性能影响。

## 9. 结论

GlobalLink系统通过结合前端密码加密、HTTPS传输加密和后端密码哈希存储，实现了多层安全防护机制，有效保护了用户密码的安全。系统设计同时考虑了安全性和可用性，确保在各种情况下都能正常运行。
